# FeatureGuard：训练与推理特征顺序的静态分析

**软件分析技术课程项目报告**　|　分析对象：Python、pandas、NumPy、scikit-learn

**摘要。** 特征矩阵有两列，不等于这两列与训练时含义相同。一旦 DataFrame 转成 NumPy 数组，模型通常只能检查列数，不能发现同名特征互换了位置。FeatureGuard 从 Python 源码恢复矩阵各列的**有序来源**，并沿同一个模型对象的训练、重训和预测过程检查这一约束。工具不读取业务数据，也不运行待检程序。项目的主要技术是前向数据流分析、有限路径区分、与调用点匹配的过程间传播，以及模型引用的别名追踪。

## 1. 一个不会抛异常的错误

加工报价中，人工每小时 80 元，设备每小时 20 元。模型训练时使用 `[labor_hours, machine_hours]`，上线后某个调用者调换了两项。一份需要人工 2 小时、设备 8 小时的订单，本应报价 `2 × 80 + 8 × 20 = 320` 元。错误程序正常返回 **680 元**。

[完整实例](../examples/reordered/quote.py)分为三份源码：训练函数创建并返回模型，通用函数按调用者传入的列表取列，报价入口调用预测。两端甚至使用同一个取列函数，单看函数体没有错误。检查结果在 `quote.py` 的预测点报告 `FG001`，列出预期顺序、实际顺序，并指回 `training.py` 的训练点及 `features.py` 的矩阵来源。检查的是原始特征的**位置契约**，不是断言报价模型具有足够精度。

| 第 9 讲：指向关系；第 10 讲：过程间指针与上下文 | 两个变量可以指向同一模型；同一工厂源码被调用两次也可以产生不同模型。训练契约附着在对象上而不是变量名上 | `_State.heap`、模型构造及 `fit` 转移；[引擎测试](../tests/test_engine.py)中的别名重训和工厂调用 |

这里**借用了课程方法，但没有照搬所有算法**。例如，第 7 讲讨论合并调用者可能引入不可行的返回路径；我们对可解析的本地函数按调用展开，而非实现通用 Super CFG 或 CFL 可达性求解器。库函数使用手写的输入输出摘要；用户函数不是预先推导并缓存的通用摘要。第 9 讲的指向关系在这里具体化为有限展开路径上的对象引用，并非整个 Python 堆的完整指针分析。工具也不使用 SMT，不声称对循环做了不动点求解。

## 3. 状态、转移与判定

一个路径状态包含名字环境 **E**、模型堆 **H** 和已记录的简单条件 **G**。名字环境区分列名列表、DataFrame、已知列序的二维矩阵、模型引用、解析后的导入符号和未知值。令 `S = 〈c₁, …, cₙ〉` 为列序列，`M(S, p)` 为列序已知、来源位于 `p` 的矩阵。**序列保留顺序和重复次数**；空序列和未知不是同一个值。

| 操作 | 对状态的主要影响 |
| --- | --- |
| `df[cols]`、`df.loc[:, cols]` | 已知 DataFrame 与显式列列表产生 `M(S, p)`；无法解析列名则返回未知 |
| `x.to_numpy()`、`x.values` | 保留来源和列序，但不再允许按列名对数组二次选列 |
| `np.concatenate([a,b], axis=1)` | 若两边的二维列序都已知，输出为两个序列首尾连接；不能把默认的按行拼接当作增加特征 |
| `q = m; q.fit(X, y)` | `q` 与 `m` 指向同一抽象对象；用本次训练的列序和位置更新其契约，覆盖旧训练 |
| `m.predict(X)` | 取同一对象最后一次可知训练的契约，逐位置比较；未知契约不能验证通过 |

逐预测位置汇总可达状态：全部匹配记为已验证；全部为纯排列错位报 `FG001`；所有已知结果均不匹配且并非全是排列错位时报 `FG002`；既有错位又有匹配或未知路径报 `FG004`；没有已知错位但证据不足报 `FG003`。对于错位，报告保留一条见证路径：首个不同的位置、两端序列和关联源码位置。**“全部”只指到达这个位置且已建模的路径。** 未运行数据校验，不能就此断言程序一定能执行到该位置。

## 4. 为什么不能独立合并两端

```python
cols = ["age", "income"] if flag else ["income", "age"]
model.fit(train[cols].to_numpy(), y)
model.predict(live[cols].to_numpy())
```

令 `A = 〈age, income〉`、`B = 〈income, age〉`。到预测点的两个可能状态是 `(训练 A, 预测 A)` 和 `(训练 B, 预测 B)`。若分别把两端都概括成集合 `{A, B}`，再取笛卡尔积，就会凭空制造两个混搭结果。FeatureGuard 在预算内保留路径状态，分别检查两个合法配对，因此不报警。对同一局部条件名和它的否定可复用简单分支事实；重新赋值时撤销旧事实。复杂布尔公式不求解。

这种精度有成本。若每个分支都独立，逐条枚举可能随分支数指数增长。默认路径预算为 **32**；超限时合并或放弃无法区分的证据，并报 `FG900`，而不是随便选一路当作事实。递归或过深的本地函数调用也停止展开。预算限制的是保留的分析状态，不是对任意输入的线性时间保证；别名、不同调用者和不同抽象堆都会带来额外开销。

## 5. 正确性与实用性实验

**实验 A：排列对照。** 对三个不同列名穷举 `3! × 3! = 36` 种训练与预测顺序配对。独立的数值参照器以三个不同的一位数表示列值，以 `(100, 10, 1)` 为位置权重；在这个构造上，六种列序必有六个不同输出。因此预期结果不需要调用分析器的比较代码即可得到。6 个同序组合均验证通过，30 个异序组合均报 `FG001`。另外 7 例覆盖缺列、多列、动态选列、分支、矩阵拼接及通过别名重训，合计 **43/43** 符合预期。这是受控子集验证，不是对任意项目的精确率估计。

**实验 B：只改变路径预算。** 对同一个[共享列配置示例](../examples/shared/quote.py)做两次检查：

| 设置 | 识别到的预测点 | 已验证 | 诊断 |
| --- | ---: | ---: | --- |
| 默认预算 32 | 1 | 1 | 无 |
| `--max-paths 1` | 1 | 0 | `FG900` 提示精度损失；`FG003` 提示无法验证 |

这个对照说明：减少分析成本会损失证明能力，但**不知道**不应被报告成**确有错位**。

**实验 C：真实模型和留出数据。** 采用 scikit-learn 随附的 diabetes 数据集，固定随机种子 42，331 行训练、111 行测试。线性回归只拟合一次；对同一批测试数据交换 `bmi` 与 `bp`，两个输入形状仍为 `(111, 3)`。实际运行中，111 行预测值均改变，平均绝对误差从 **42.156** 变为 **395.705**。静态检查不加载数据，定位到两个预测点，其中正确顺序验证通过，换列处报 `FG001`。这说明形状检查可能漏掉代价很高的错误，不代表所有模型的误差都会如此变化。数据版本、指标定义和复现步骤在[案例记录](case-study.md)。

## 6. 边界、复现与结论

**可解释的边界。** 假定原始 DataFrame 有普通、唯一的单层列标签，按名称选列能成功；对动态生成的列名、未知变换、原地修改及不支持的控制流，分析可能失去证据。若输入含重复标签、拟合环境与部署环境不同，或同名特征的单位发生变化，有序列名相等也不等于语义相同。模型通过 pickle、joblib 或服务接口跨进程交接时，本版不把两个碰巧同名的变量认作同一个模型。所有路径都无法识别接收者时，该方法调用不算已识别预测点；评审务必同时看 `predictions` 与 `verified`，而不是只数告警。

**复现。** 在仓库根目录使用 Python 3.10 或更新版本：

```sh
python3 -m featureguard examples/reordered/quote.py
python3 -m featureguard examples/shared/quote.py --max-paths 1
python3 -m tools.experiment
python3 -m unittest discover -s tests -v
```

前两条预期退出码为 1，后两条应为 0；均不需要安装机器学习库。只有主动执行案例中的训练程序才需要 pandas、NumPy 和 scikit-learn。

**结论。** 最有价值的分析事实不是“两个变量都装着数组”，而是“在这一条路径和这一次模型训练中，每个位置都代表哪个特征”。前向数据流提供顺序，过程间传播连接训练和服务代码，别名追踪保证比较的是同一模型，路径区分防止报告不存在的错位。四者的贡献都可以通过代码和对照实验检查。
